# B 없이 A 화면 확인하기: localhost MOCK

대상 기준: develop `79a31db`의 A+C 소스, 사용자 작업 브랜치 `feature/a-ui-check`.
이 도구는 **실제 인증·DB·C AI 서비스가 없는 화면 테스트 서버**입니다. production `app/main.py`, A JS/CSS, B 파일을 수정하지 않습니다. 기존 HTML/JS/CSS를 읽고, 가짜 API 결과를 돌려줍니다. 일반적인 배포 서버로 실행하거나 인터넷에 공개하지 마세요.

## 1. 파일 복사

ZIP 안의 다음 새 파일 4개만 기존 저장소의 같은 경로에 복사합니다. 저장소 전체를 덮어쓰지 않습니다. 기존에 같은 이름의 파일이 있다면 덮어쓰기 전에 비교합니다.

- scripts/preview_a_ui.py
- scripts/preview_a_ui.js
- tests/test_preview_a_ui.py
- docs/A_UI_PREVIEW.md

저장소 최상위 폴더는 `app`, `scripts`, `tests` 폴더가 함께 보이는 위치입니다. PowerShell을 그 위치에서 엽니다.

```powershell
git status --short --branch
```

브랜치가 `feature/a-ui-check`인지, 기존 변경 파일은 없는지 확인합니다. 이 도구를 위해 checkout/reset/clean/pull을 할 필요는 없습니다. 기존 미커밋 작업이 있다면 그대로 보존합니다.

## 2. 한 명령으로 실행

```powershell
py -3.12 scripts/preview_a_ui.py
```

Python 표준 라이브러리만 사용합니다. pip 설치, .env 수정, API 키, DB 준비, Node 설치가 필요 없습니다. Windows에서 Python 3.12 실행기가 없다는 오류가 나면 현재 설치된 Python 버전을 먼저 확인합니다. 설치/환경 변경 없이 임의 명령을 이어서 실행하지 마세요.

터미널을 켜둔 채 브라우저에서 다음 주소를 엽니다.

http://127.0.0.1:8765/login

포트가 사용 중이면 `py -3.12 scripts/preview_a_ui.py --port 8766`을 실행하고 출력된 주소를 사용합니다. `localhost` 대신 출력된 `127.0.0.1` 주소를 사용합니다. 서버는 이 주소에만 바인딩하고 Host/Origin을 검사합니다.

## 3. 첫 화면부터 순서대로

1. 모든 페이지 위에 노란 `MOCK / A UI 전용 테스트` 안내가 보이는지 확인합니다.
2. 회원가입 링크를 엽니다. 이메일/비밀번호/확인은 고정 가짜 값이며 수정할 수 없습니다. 실제 정보를 입력하지 마세요. 회원가입을 누르면 로그인으로 이동합니다. 실제 계정은 생성되지 않습니다.
3. 로그인 버튼을 누르면 작업 화면으로 이동합니다. 진짜 인증 확인이 아니라 화면 이동만 확인합니다.
4. `＋ 새 릴스 기획`을 누릅니다. 대화 제목, 오른쪽 제작 조건, 입력창을 확인합니다.
5. `20대 자취생에게 아침 메뉴를 소개하고 싶어요`를 보내면 가짜 후속 질문/선택지가 나옵니다.
6. 제안 버튼을 클릭하고 보내거나, 아무 테스트 문장을 한 번 더 보냅니다. 두 번째 메시지에서 고정 30초 제작 조건으로 준비 상태가 됩니다. 입력을 실제로 해석하지 않습니다.
7. `이 조건으로 대본 작성`을 누릅니다. 3개 장면의 0–10/10–20/20–30초 구간, 자막·대사·화면·연출, 원리, 출처/라이선스 표시를 확인합니다.
8. 입력창에 `대사를 더 짧게 해줘`를 적고 `입력한 내용으로 대본 수정`을 누릅니다. 버전 2와 수정 설명을 확인합니다. 일반 `보내기`는 수정이 아니며 MOCK 기획 흐름으로 돌아갑니다.
9. 다른 대화를 만들고 기존 대화로 돌아옵니다. 새로 고침 및 `새로 불러오기` 후 동일한 내용인지 확인합니다. 서버를 끄면 내용은 사라집니다.
10. 상단 `페이지네이션용 25개 대화/기록`을 누릅니다. 대화 더 보기(20+5), 이전 메시지 보기(20+5), 오래된→최근 메시지 순서를 확인합니다. 여러 번 누르면 샘플이 누적되므로 필요시 초기화합니다.
11. 상단 오류 선택에서 하나를 고른 뒤 메시지를 보냅니다. 다음 채팅에 한 번만 적용됩니다. 409 충돌/처리 중, 504 timeout, 502 잘못된 AI 응답, 503 사용 불가에서 오류 문구·버튼 복구·입력 보존을 확인합니다. 선택 UI 표시는 그대로여도 오류는 한 번만 적용됩니다. 다시 적용하려면 정상으로 바꾼 뒤 원하는 오류를 다시 고릅니다.
12. 401은 로그인 화면 이동을 확인합니다. 다시 MOCK 로그인하면 이전 메모리 기록을 볼 수 있습니다. `로그아웃`도 확인합니다.
13. 상단 `모두 초기화`를 누르면 대화/기록/가짜 로그인 상태가 초기화되고 로그인 화면으로 갑니다. 종료는 터미널에서 Ctrl+C입니다.

## 4. PC/모바일·접근성 점검표

실제 브라우저 화면 검사는 아래 칸을 직접 확인한 뒤 체크합니다. 자동 테스트 성공만으로 체크하지 마세요.

- [ ] PC 1440×900: 세 영역 배치, 긴 대본/참고문헌 줄바꿈, 고정 입력창 가림 없음.
- [ ] DevTools 기기 모드 390×844와 360×800: 가로 넘침 없음, 대화 목록 스크롤, 기획/대본 버튼 접근 가능.
- [ ] 768px/1100px 부근: 반응형 영역 전환, 페이지 이동/대화 선택 정상.
- [ ] 키보드 Tab/Shift+Tab/Enter: 포커스 표시, 입력/버튼 접근, 오류 확인.
- [ ] 200% 확대: 제목/버튼/입력창 사용 가능.
- [ ] 새로 고침, 다른 대화 선택, 이전 기록 더 보기에서 기록 중복/손실 없음.
- [ ] DevTools Console: 오류 없음. Network: 요청은 127.0.0.1만 사용.
- [ ] 노란 MOCK 안내가 보이고 실제 비밀번호를 입력할 수 없음.

이 서버는 127.0.0.1 전용이므로 **실제 휴대폰에서 PC IP로 접속하는 검증은 하지 않습니다.** 모바일은 PC DevTools 기기 모드로 확인합니다. 실제 휴대폰/배포 브라우저 검증은 B 통합 이후 별도로 합니다.

## 5. 자동 확인

```powershell
py -3.12 -m unittest discover -s tests -p test_preview_a_ui.py -v
```

Node가 이미 설치돼 있으면 기존 A 테스트도 실행할 수 있습니다. 이 미리보기를 쓰기 위해 Node를 설치할 필요는 없습니다.

```powershell
node tests/browser_clients.mjs
node tests/workspace_clients.mjs
```

제작 환경 확인 결과: Python HTTP 테스트 11개 통과, 기존 브라우저 클라이언트 DOM stub 9개 통과, workspace DOM stub 10개 통과. C의 실제 `Brief`/`ScriptDraft` DTO로 고정 fixture 두 버전의 형태와 장면/출처 ID 연결도 검사했습니다. 이것은 **C 실행/품질 검증이 아니며**, 브라우저 시각 검증도 아닙니다. 사용자 Windows에서는 위 명령으로 다시 확인해야 합니다.

## 6. 명확한 한계와 B 통합 후 남는 작업

- 가짜 로그인은 단일 프로세스 공유 상태입니다. 세션 쿠키, 암호화, 사용자 격리, 보안, 회원가입 유효성, 비밀번호 저장/검증을 구현하지 않습니다. 모든 탭은 같은 가짜 사용자입니다.
- 비밀번호 입력은 HTML 단계에서 readonly 고정 MOCK 값으로 대체합니다. 서버는 정확한 가짜 값만 허용하며 계정/비밀번호를 상태·파일·로그에 저장하지 않습니다. 개발자 도구 등으로 입력 보호를 해제하지 마세요.
- AI를 호출하지 않고 정해진 응답만 제공합니다. 브리프 추출, 검색 정확성, 후속 질문 품질, 수정 의도 반영, 실제 C 오류 복구를 검증하지 않습니다.
- timeout은 즉시 504를 반환하는 모의 오류입니다. 브라우저의 실제 135초 타임아웃이나 요청 중단, 느린 네트워크/동시 요청/DB 트랜잭션/처리 잠금은 검증하지 않습니다. 실제 대기 UI는 DevTools 네트워크 지연으로 별도 관찰할 수 있으나 backend 검증을 대신하지 않습니다.
- 출처 데이터는 저장소의 실제 카드/출처 정보를 읽습니다. 기본 링크 클릭은 외부 이동을 차단합니다. 휠 클릭/우클릭 새 탭 열기는 브라우저 기능으로 외부 이동할 수 있으므로 이 테스트에서는 사용하지 마세요. 자동 외부 호출은 없습니다. 외부 출처 유효성이나 저작권의 추가 검증 결과를 의미하지 않습니다.
- 허용한 CSS/JS/HTML/테스트 라우트만 제공합니다. .env나 저장소 전체를 정적 파일로 공개하지 않습니다. production 앱을 import하거나 환경변수/API 키를 읽지 않습니다.
- 이 ZIP은 새 파일 4개만 포함합니다. 실행은 기존 A 템플릿/정적 파일/C 참고 데이터가 있는 저장소에서 해야 합니다.
- B 병합 후 실제 회원가입→로그인→대화 생성→C 호출→DB 저장→로그아웃/재로그인→기록 복원, 소유권 검사, 경쟁 요청, 배포/실제 모바일 검증을 별도로 진행해야 합니다.

발견 사항 기록: 화면/브라우저 크기, 재현 순서, 기대 결과, 실제 결과, MOCK인지 실연동인지, 스크린샷을 남깁니다. 이 단계에서는 인증/DB/실제 AI 기능을 완료로 표시하지 않습니다.


## 로그인 화면이 흰 화면에서 계속 로딩될 때 (미리보기 수정판)

기존 단일 연결 서버에서 브라우저가 미리 열어 둔 빈 연결 때문에 다음 페이지 요청이 대기하는 현상을 로컬에서 재현했습니다. 사용자 PC의 원인이 반드시 이것이라고 확정한 것은 아닙니다. 수정판은 다중 연결 처리, 5초 연결 유휴 제한, 공유 MOCK 상태 잠금을 사용합니다. 빈 연결 및 불완전한 헤더 연결을 동시에 열어 두고도 로그인/JS가 응답하는 회귀 테스트를 추가했습니다.

1. 미리보기 터미널에서 Ctrl+C로 기존 서버를 종료합니다.
2. 수정 ZIP의 scripts/preview_a_ui.py, tests/test_preview_a_ui.py, docs/A_UI_PREVIEW.md를 같은 경로에 덮어씁니다. 이는 이 미리보기의 파일만 교체하며 production 파일은 변경하지 않습니다. 최초 ZIP의 scripts/preview_a_ui.js는 그대로 필요합니다.
3. `py -3.12 scripts/preview_a_ui.py`로 다시 실행합니다.
4. http://127.0.0.1:8765/login 에서 Ctrl+F5로 다시 불러옵니다.
5. 여전히 로딩된다면 오류/화면과 터미널 상태를 확인합니다. 방화벽/보안 프로그램을 끄거나 바인딩 주소를 바꾸지 마세요.

이 수정은 브라우저 연결 수용 문제에 한정됩니다. 실제 B 동시성/DB 잠금 검증은 아닙니다.
